# 2026-11-10 - Phase 0a: integrity hotfix (spec findings P-16 .. P-21)

**Asked:** implement `PRAMAAN_V2_OVERHAUL_SPEC.md`. Started with Phase 0a, the P0 truth-in-UI fix, as the spec orders.

## Root cause found (P-16)
`apps/web/src/app/admin/page.tsx` sent `POST /v1/admin/claims/{id}/verify` with `{status: "document", confidence: 0.97}`
and nothing else; the endpoint accepted any status and confidence from any admin (including the profile's owner). A
certificate then printed that claim as "Document-verified" regardless of evidence, and the status banner said
"Verified" for any `approved` profile. That is exactly the screenshot-6 state (agents escalated, 0 evidence, holder
match 75%).

## Changed
- **TRU-00** `services/certificates.py::backed_claims` (I-8): a claim is printed only if evidence of its kind exists
  (`web` needs a source URL + quote; `document` needs a document-evidence row whose file matched the holder at >= 0.85
  with no flags; `human` needs the reviewer's reason + evidence reference). Unbacked claims are left off, never
  downgraded in the label. New `human` status; the override endpoint can only produce `human`/`self`, requires a
  reason (>= 10 chars) and an evidence reference, caps confidence at 0.9. `Profile.decision_basis`
  (`automation` | `reviewer`) is the server enum the UI words its banner from (I-9). No self-review on status change,
  claim override or review resolve (I-10). Verification runs are idempotent (a running run is returned, not restarted).
  `scripts/audit_certificates.py` finds (and with `--revoke` revokes) existing certificates whose evidence is gone.
- Lipik: a name that matches only partly (0.6-0.85) is now flagged `partial_match` and no longer reported as
  "Holder matches"; Prahari escalates it.
- **TRU-02** `claim_specifics_in_quote`: every number/year in a claim must appear in the cited quote (P-17).
  Applied in Pariksha and in the eval harness. Wikidata is used only for the item the applicant confirmed
  (`wikidata_qid`; endpoints `GET .../wikidata-candidates`, `POST .../wikidata-confirm`; UI card in the Verify tab)
  (P-18).
- **CRT-01** certificate render aborts, and fails on, any request not to our own web/API origin (P-19).
- **PG-00 (partial)** certificate wording, badges, onboarding banner and chat copy come from the evidence class / server
  enum; "independently" only when every claim is `document`/`issuer`; no emoji; admin override dialog with reason +
  evidence; Verify panel gets its own height on small screens (P-21).
- Migration `0004_decision_basis_wikidata`.
- **OPS-01** `AGENTS.md`, `agent-logs/`.
