## INCIDENT: test data written to the hosted database
The repo `.env` sets `DATABASE_URL` to a Supabase (hosted) Postgres. The API I started for screenshots read it. The smoke suites call the API (register users, create profiles, admin approve) so they created test records in the HOSTED database, while their `sql()` helper runs against the LOCAL docker db, so those flows are inconsistent. Two runs of `smoke-pages.mjs` and one start-up were done against it. Records are named like `Bio Proof <tag>`, `Demo Replay <tag>`, users `*@example.com`. Nothing was deleted or edited by me. The API was stopped afterwards. Owner decision needed: list and remove them, or leave.
Going forward: run the API with `DATABASE_URL` pointed at the local docker db (`postgresql+asyncpg://pramaan:pramaan@localhost:5432/pramaan`), never the hosted one.
